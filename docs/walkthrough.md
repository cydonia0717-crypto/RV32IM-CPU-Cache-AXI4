# 代码阅读与项目讲解

## 推荐阅读顺序

1. `rv32_soc.v`：画清 CPU、I/D Cache 和 AXI 桥的连接，区分 CPU 单字请求和 Cache 16B 回填请求。
2. `rv32_muldiv.v`：从除零、最小负数、MULHSU 入手理解符号恢复，再看每拍移位/减法。
3. `rv32_cache.v`：沿着读命中、读缺失和写三条路径理解状态机，重点看 valid、failed、poison。
4. `rv32_axi_bridge.v`：看锁存 owner、轮询优先级、AW/W 各自 pending 位，以及 BREADY 条件。
5. `rv32_core.v`：先看每级 valid 和传递条件，再看前递、load_hazard、redirect，最后看解码和 CSR。
6. `tb_soc.v` 和 `reference.py`：从 trace 字段追一次指令，了解如何由独立模型发现错误。

## 三条值得手算的路径

### load-use

```assembly
lw x5,0(x8)
add x6,x5,x5
```

先查 EX/ID 是否同时存在形成相关；若 load 已在 MEM 等待，则 EX 无法前进。load 响应到达后 MEM 将数据符号/零扩展，并向 EX 两个源操作数前递。暂停期间保存前递值，保证以后生产者离开也不会重新使用旧寄存器值。

### store 的 AW/W 解耦

CPU 将地址、数据、WSTRB 锁在 MEM，D-Cache 再锁存，桥最后锁存到 write_addr/write_data/write_strb。桥同时提供 AWVALID/WVALID，各自握手后各自清 pending。两者都完成后才接收 B。写失败形成同步异常，Cache 不发布命中更新。

### FENCE.I 和在途取指

软件先写入新机器码，写直达保证存储器已更新；FENCE.I 等旧指令排空，再清 I-Cache valid。已有回填记录 poison，CPU 清 IF/ID 并标记旧取指响应为 drop。新 PC 从 FENCE.I 下一条开始取，测试通过调用被修改函数验证最终执行的新指令。

## 可以据实介绍的项目内容

项目实现了一个 RV32IM 五级顺序流水线，包括 MEM/WB 前递、load-use 互锁和分支冲刷。I/D Cache 各 4KB、16B 行；D-Cache 采用写直达和写不分配，读缺失通过 4 拍 AXI burst 回填。M 扩展用 32 拍迭代运算，避免组合乘除法路径。验证使用独立 Python 指令模型做逐条差分，44 组系统回归核对了 83,620 条记录，并运行了编译得到的 C 程序。

面试中应能解释源码、独立复现测试，并根据实际参与程度说明工作。阅读和运行工程之后，再将已经理解、能够复现的内容写入简历。

## 常见追问

| 问题 | 该工程的具体答案 |
|---|---|
| 是否支持乱序？ | 指令顺序执行/退休；AXI 每类最多一个事务在途，不实现多事务乱序返回。 |
| load-use 为什么要停？ | 数据在 MEM 响应完成前不可用，ID 相关指令等待，完成后通过 MEM 前递。 |
| 什么情况需要 WB 到 ID 旁路？ | 同拍读写相同寄存器时，ID 显式取 WB 数据，避免依赖寄存器堆实现。 |
| 写直达为什么等 B 才更新缓存？ | 避免总线写失败时 Cache 留下尚未成功提交的新数据。 |
| 怎么保证 4KB 不跨界？ | 回填起点 16B 对齐、固定 16B；写为单个对齐 word，因此天然不跨界。 |
| 稀疏或多路相联有没有？ | 当前为直接映射；同 index 不同 tag 会替换，并有冲突测试。 |
| 乘除法用了组合运算符吗？ | RTL 用移位、加法、比较、减法，每个 M 运算 32 拍；Python 模型独立用整数运算。 |
| 精确异常怎么实现？ | 故障指令按顺序到 MEM，禁止故障访存/写回，清年轻指令，保留老 WB，记录 mepc/cause/tval。 |
| 如何定位真实 bug？ | 算术右移在 PC=0x44 首次差分出错；沿 trace 看源值和符号上下文，修复条件表达式并回归。 |
| 时钟能达到多少？ | 已跑功能验证和通用结构综合；目标工艺或 FPGA 确定后才能给出频率与 STA 数据。 |
| CPI 为什么高于 1？ | 单请求取指、Cache LOOKUP 延迟、阻塞 store、分支冲刷和随机总线等待；C 测试约 4.57。 |
